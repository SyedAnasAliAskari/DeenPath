# DeenPath 0.3.0 limitations

- No Android phone is connected. Actual audio, notifications, overlay, reboot, sensor direction, biometric unlock and document-picker backup/restore remain device qualification tasks. A successful scheduling/build result is not proof of delivery.
- No live hosting configuration or AI keys were supplied. PHP/MySQL HTTP integration, cross-account SQL/file access, email and actual Gemini generation are unverified. The existing API must receive the additive SQL migration before new entities sync.
- Gemini is the only implemented AI provider family, with separate personal billed/free-tier connections. Other paid providers are not advertised as supported. The user must satisfy Google's current age, region and professional/developer eligibility restrictions. There is no automatic Google OAuth project/quota provisioning, shared app key or unlimited free entitlement. Rasikh is disabled until official capabilities/terms can be verified.
- AI explanations/citations are not certified religious rulings. Matching bundled references display the source but do not prove the model's interpretation or quoted wording. Six starter reflections and fifteen attributed Quran excerpts are included; no new Hadith corpus or fasting curriculum has been fabricated. Additional scholarly content requires review and licensing.
- Private cloud ciphertext needs the user's exported recovery backup/password on another installation. The server cannot reset that encryption key. PIN/biometric privacy is a separate gate; the whole SQLite database is not encrypted. Browser private data is ephemeral. Provider keys never sync and require re-entry after reinstall.
- Chat context and saved conversations retain bounded recent messages (up to twenty messages / roughly 20,000 text characters per saved conversation); device history retains fifty conversations. There is no infinite transcript archive. Connection tests can consume quota or incur charges.
- Private reminders are deliberately generic. Detailed habit/admission names are not shown in notifications, the home screen or general Progress. Individual recovery task reminders are scheduled from unlocked edits; encrypted cloud changes on a new device require unlocking/refreshing the private section before its local reminder metadata is rebuilt.
- Check-in occurrence counts and per-occurrence generation are capped at 1,000 per day to bound offline processing. Correcting an admission removes obsolete pending activities but retains activities already completed voluntarily. History and optimistic conflict review prevent silent shared-counter decrements.
- Civil Hijri dates are calculated, adjustable estimates and can differ from local moon sightings. Qibla uses a spherical initial bearing and available rotation-vector sensor with geomagnetic declination; interference, tilt and missing hardware affect accuracy. No paid mapping service is used.
- Native WorkManager/inexact alarms, force-stop, DND, volume and OEM restrictions remain controlled by Android. Private reminders respect quiet hours; prayer reminders retain separate controls. Travel updates run only while the app is in use and do not decide qasr/jam' rulings.
- Personal-record events are detected when Progress is viewed; they are not an always-running background achievement service. Streaks are reconstructed from eligible records, so legitimate historical corrections can change the derived best. General milestone encouragement is informational, not an assessment of religious reward.
- APK is debug-signed, not a production-signed store release. Trademark/name availability, final scholarly review, provider distribution terms and physical-device/hosting integration qualification remain required before public launch.
