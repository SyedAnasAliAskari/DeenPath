# DeenPath v0.3.2

Install `DeenPath-0.3.2-debug.apk` over the existing app. Do not uninstall or clear its data. This update keeps the Android app ID, signing key, account format and database schema.

## Changes

1. Reminders name the prayer, including Jummah on Fridays. Routine notifications keep the routine name. The test explicitly says “Fajr prayer — test reminder”; it does not record a prayer. The overlay fills the available screen, has a scrolling verse, and can be closed with Back or its close button. Android system controls remain accessible. It does not cover the lock screen.
2. English now uses Saheeh International and Urdu uses Muhammad Junagarhi, downloaded verbatim from [Tanzil](https://tanzil.net/trans/). All 15 references have both full translations. The translator is shown in the reminder and reading view. Arabic remains the original Tanzil text. These are published translations, not generated paraphrases; different editions can word a verse differently. Translation licenses and source hashes are retained.
3. Android Back closes the current dialog or reader first. A settings category returns to the settings list; a page returns Home. Prayer details, correction forms, private editors and Guidance settings close before leaving their page. Back from Home puts the app in the background.
4. Friday’s midday slot defaults to Jummah. The prayer report and progress streaks include a separate Jummah row. An explicit Dhuhr choice is still available in the Friday correction form. Both choices use the same saved midday ID, so a Friday still has five obligations and existing records are retained.
5. Qibla has a rotating north dial, smoother movement across north, and clear turn-left/right guidance. The browser shows a static north-based bearing because it has no native sensor. Travel buttons, routine notes, private forms and other panels have more spacing. Travel and Qibla now open location settings directly.
6. The routine editor has a visible Dua text field and a PDF/image upload. Text and an attachment can be saved together and opened from the routine. Existing file storage and size limits still apply.
7. Protection is now Personal repentance. You can add an activity directly, without first recording a slip. A habit can also have an optional personal penalty; its fields appear when enabled. These are personal commitments, not prescribed religious punishments. Existing encrypted records are preserved.
8. Settings uses short labels: Your account, Language / Appearance, Location & prayer times, Reminders & sound, and Backup & sync. Extra location controls are tucked under More location options. Permission setup is visible in reminder settings.

## Background reminders

The native snapshot save now rebuilds the SQLite reminder queue before reporting success. A due reminder survives a simultaneous edit instead of being discarded while future plans are replaced. An Android alarm receiver holds a short bounded wake lock while dispatching; it does not rely on the WebView staying open. A periodic worker checks for recent due items and renews future plans. One dispatcher alarm remains in use, preserving the fix for the 500-alarm limit.

On your phone:

1. Open **More → Settings → Reminders & sound**. Enable prayer reminders if wanted.
2. In **Set up reminders**, allow Notifications and **Alarms & reminders**. Without the latter, Android can delay delivery. For the full-screen overlay, enable Show above other apps and grant its permission.
3. Tap Test notification, then press Home and wait. Test the overlay the same way with the phone unlocked. Tests are scheduled for about 15 seconds later.
4. Create a routine a few minutes ahead, return to the phone’s Home screen, and check delivery. Repeat after swiping DeenPath away from Recents. If your phone restricts background use, open Battery settings from the reminder setup section.
5. After using Android **Force stop**, open DeenPath once. Android blocks stopped apps until they are opened again. The app cannot bypass that restriction.

[Android alarm documentation](https://developer.android.com/develop/background-work/services/alarms) explains exact-alarm permission and inexact delivery limits.
