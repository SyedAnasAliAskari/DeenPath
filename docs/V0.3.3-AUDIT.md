## Code-path findings

- Native alarm → single SQLite dispatcher → notification/overlay: delivery did not explicitly write prayer completion in the audited v0.3.2 code. Elapsed prayer windows already become unknown, not automatically missed/completed. Preserve that distinction.
- Browser Remind Later and native overlay snooze were separate paths. No unconditional completion write was found in either original snooze branch; the reported physical-device symptom was not reproduced on a connected phone. Centralized typed native actions, explicit button types, validation, stale-event/account checks and regression tests now protect those paths. This is not a claim that an unobserved device symptom was independently reproduced.
- A concrete Qaza bug was found: `main.tsx` scheduled an immediate `category: qaza` notification after saving Qaza. That post-completion reminder has been removed. Explicit Qaza now updates the identified obligation once.
- Overlay completion independently wrote SQLite snapshots and sync operations, without a shared notification action dispatcher or durable consumed-event checks. Actions now share `PrayerActions`, and native completion still commits prayer/Qaza records and queued operations through the existing SQLite snapshot transaction.
- Native Qibla already used the geographic Kaaba bearing, display-rotation remapping and magnetic declination. These were preserved and extracted into testable sensor math; no claim is made that smoothing fixes physical sensor accuracy.
- Garden plants already use completed routine counts, seven completions per growth stage, capped at stage four. The widget applies the same saved-data rule, without fabricating plants/rewards.
- The existing SQLite schema, encrypted private records, account scope, three-way snapshot merge, API, PHP/MySQL schema, provider fallback and conversation storage are retained. No server/database migration is needed.
