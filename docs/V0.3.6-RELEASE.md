# DeenPath 0.3.6

Android version code 9. This release includes the Secrets, attachment and Enforcer work from 0.3.5 and adds the requested prayer backlogs and location repair. The project folder remains SalahGuide.

## Prayer stacks

Prayer now has separate Qaza and Nafl card stacks below today’s five prayers. Swipe or use the arrow buttons to browse. Completing a card removes that item and advances the stack. Unfinished entries survive reload and midnight.

Qaza includes confirmed misses, earlier Qaza quantities and elapsed unrecorded prayers. Unrecorded entries are explicitly labelled: completing Qaza there confirms that the prayer was missed. Merely opening or browsing the stack never invents a missed/completed prayer. Choose “Include prayers from” to include yesterday or an earlier date; known older records remain included. The tracking start is retained from the first launch, rather than moving forward every day when there are no prayer records.

Recurring Nafl entries accumulate by their original scheduled period, including selected prayer starts. A completion closes only that period. One-off Secrets Nafl penalties remain single entries until completed; they do not multiply every day. Historical Qaza quantities decrease one prayer at a time. These changes do not turn Qaza or Nafl into on-time Fard records or grant routine Freeze Points.

## Location

Android tries its available fused/network/GPS providers together instead of relying on one GPS request. An early null result no longer aborts the request. Recent usable locations can be reused (up to two minutes immediately, with a bounded 15-minute fallback); stale, invalid and very inaccurate positions are rejected. Requests have one terminal result and clean up their callbacks after success or timeout. Approximate location permission remains supported.

Automatic refresh retains the saved city quietly if a fix is unavailable. Manual detection offers useful recovery guidance and the existing city picker; coordinates do not need to be typed to use that fallback. Successful detection refreshes the visible location fields. Permission and device Location settings still need to allow access; no app can guarantee a GPS fix indoors or with Location disabled.

## Verification and installation

83 TypeScript logic tests and 62 Android unit tests passed. All 35 browser checks passed across the final run and one rerun after the preview was briefly rebuilt during navigation. Android assemble, unit tests and lint passed: 0 lint errors, 87 warnings. Existing Vite bundle-size/dynamic-import notices remain.

The authorized Infinix X6725B accepted the in-place update to 0.3.6. Both prayer stacks rendered without horizontal overflow. Native location detection returned a recent 100-metre-accuracy fix. The pre-existing automatic-location option updated saved settings; all non-settings records, including worship, remained unchanged. Native PDF rendering returned two distinct pages from a temporary two-page fixture, which was removed. Screen timeout was restored to its original 60 seconds and temporary ADB forwarding was removed. No test worship, private admissions or PIN changes were made.

Install DeenPath-0.3.6-debug.apk over the existing app. Do not uninstall or clear storage. App ID and signing certificate are unchanged. Prior deliverables are preserved. No database migration is required from 0.3.4 or 0.3.5. Older private backends need the bundled After Namaz support introduced in 0.3.4; retain hosting configuration and never import install.sql over an existing database.

Hosted backend/cloud deletion, every location-provider failure combination, actual biometric interaction, reboot/long Doze delivery and other OEM devices remain outside this verification.
