## Timed reminder observations and remaining limitation

| Scenario | Actual observation |
|---|---|
| App foreground, screen on | Synthetic notification and Enforcer appeared |
| App in background on Home | Delivery was delayed; no receipt stage was recorded by observation time |
| Locked, screen off | Device remained Dozing; no reminder receipt or Enforcer activity appeared |
| Removal from Recents | Recovery callback fired and service stayed foreground; process entered do_freezer_trap and synthetic delivery failed |
| Reboot, explicit process termination, notification-denied and battery-optimized variants | Not retested on this final update |

All ordinary notification, exact-alarm, battery-exemption, overlay and full-screen grants were present during the observed failure. Passive inspection returned `do_freezer_trap` for the app process while Android still reported its prayer service as foreground. Starting QA/foreground work later allowed the process to run again. This is a delivery-stage failure before the Enforcer activity can launch; automatic background/locked delivery remains unresolved on this Infinix. The app must not be described as fully qualified for unattended locked-screen reminders.

The app uses normal reminder alarms, notification/permission checks and the existing explicit screen-wake option. It does not add app-usage monitoring, accessibility workarounds or an alarm-clock scheduling disguise. Android can throttle idle alarms, so the selected one-minute cadence is not a universal sleep-delivery guarantee.
