# DeenPath v0.3.4

Routines, reflection and native reminder UI update. The application ID remains `org.salahguard.app`; version name is `0.3.4`, version code `7`, minimum API 29 and target API 36. The project folder remains SalahGuide. Earlier release artifacts are retained.

## What changed

- Routines have separate Tasbih, Dua, Quran, Nafl and personal-routine card stacks. Complete a card, then swipe it left/right or use the next-card button. Moving a completed card does not delete its history or complete the next one. Reduced-motion preferences are respected.
- Every routine kind can attach a PDF or supported image. Text and attached files have separate reading controls and use the existing local/cloud document storage.
- Popular editable tasbih presets include Astaghfar, Kalma Shahadah, Durood Shareef, SubhanAllah, Alhamdulillah and Allahu Akbar. Targets are personal goals; adding a preset does not complete it.
- The new **After Namaz** frequency lets you choose Fajr, Dhuhr, Asr, Maghrib and/or Isha. A fresh counter period begins when a selected prayer TIME STARTS, even without a prayer completion and after reopening the app. Earlier counts/completions remain saved. Recording a prayer or Qaza does not trigger a reset.
- The location, timezone, calculation method, Asr choice and adjustments displayed at creation define that routine's prayer schedule. Create a new routine to change its schedule, keeping historical periods stable. These cycles do not earn daily Freeze Points.
- Statistics use clearer summary cards, separate prayer streak cards, a seven-day activity chart and routine summaries. Garden has its own prominent destination within Progress, opening the existing saved-data Garden.
- Repentance creation puts name and encrypted description first, followed by the chosen Tasbih/Nafl/custom personal penalty. Reminder date/time controls appear only after an explicit checkbox. Unchecked reminders are not silently enabled. Privacy controls appear above the flow.
- Android private space can use an opt-in biometric lock, a PIN, or both. Biometric enablement happens only after Android authenticates successfully. Existing encryption/key material and account scope are retained; changing accounts during authentication rejects the callback. Private text is not stored as plaintext in browser local storage.
- Visible Back and Android Back return through actual navigation history, including Prayer subviews, Progress/Garden and Learning. Dialogs, readers and private editors close before leaving their screen.
- Enforcer has a compact brand/close row, a separate live timer panel, time-progress bar, rounded primary/secondary actions and a centered overlay with side margins. Notifications use a clearer accent/category and explicit completion, snooze and close actions. Widgets have softer surfaces, clearer typography and thinner progress bars. Daily widget refresh also schedules the next relevant routine reset boundary.
- Native Singapore rounding now agrees with the frontend and backend, verified against shared method/location/season fixtures. Unavailable start schedules disable counting instead of inventing times.

## Install and hosting update

Install `DeenPath-0.3.4-debug.apk` over the existing app with `adb install -r` or the Android package installer. Do not uninstall or clear storage. The signing certificate SHA-256 remains `3b6d1d3a4c7b5a85c93cdf24874834b875b9e4ed17d0b7b40ee244a3ee0dd55f`.

The authorized Infinix X6725B accepted the in-place v0.3.3-to-v0.3.4 update. A fresh private backup and comparison confirmed existing records, pending operations, settings, account scope and user files were retained. A later normally unlocked phone pass reviewed the Enforcer, timer/Close, notification, Daily widget, routine form controls and Statistics/Garden/Back; its current data was unchanged afterward. Device captures and backups stay excluded under `.tools/device-qa`.

**Deploy the updated private backend source before syncing After Namaz routines to an existing hosting account.** Its new frequency and server-side time validation need this version of `backend/src`, including `PrayerStarts.php` and `ADHAN-LICENSE.txt`. The bundled private-backend archive includes these files and needs no Composer or production Node process. Preserve the existing hosting configuration and credentials. No MySQL/SQLite schema migration is required; do not import `install.sql` into an existing database.

## Verification and limits

See [test results](review-v0.3.4/TEST-RESULTS.md) and [device notes](review-v0.3.4/DEVICE-QA.md). Automated tests are separate from physical-device and hosted-backend qualification. The PIN/biometric configuration was not changed on the user's phone for testing, and no false prayer/routine completions were inserted there. No production database or live account/provider integration was exercised.

Android/OEM restrictions on overlays, full-screen intents, alarms, Doze and screen wake remain applicable. v0.3.3's phone check observed delayed screen-off delivery, and this visual pass also observed a delayed initial background preview; the redesign does not remove that reliability limit. Live biometric authentication, permission-denial combinations, reboot/long-Doze behavior, physical compass calibration and other OEM launchers remain manual acceptance cases.

Prayer-start PHP calculations are derived from the installed MIT-licensed [Adhan JS implementation](https://github.com/batoulapps/adhan-js), with its license included in `backend/src/ADHAN-LICENSE.txt`.
