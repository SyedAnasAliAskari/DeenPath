# DeenPath v0.3.3 — upgrade and verification report

This build was installed over v0.3.2 on the user's Infinix X6725B (Android 15) with existing records, settings and files retained. Device checks are documented in [DEVICE-QA.md](review-v0.3.3/DEVICE-QA.md); unexecuted cases and live-backend acceptance remain open.

## Install without losing data

1. Keep the existing app installed. Do not uninstall, clear storage or reset its database.
2. Use `deliverables/v0.3.3/DeenPath-0.3.3-debug.apk`. Install through the phone's file manager, or use an authorized USB device with `adb install -r deliverables/v0.3.3/DeenPath-0.3.3-debug.apk`.
3. The application ID remains `org.salahguard.app`. Version name is `0.3.3`, version code is `6` (previously `0.3.2`/`5`). Minimum API 29, target API 36.
4. The debug signing certificate must match the installed app. The v0.3.2 and v0.3.3 build certificate SHA-256 is `3b6d1d3a4c7b5a85c93cdf24874834b875b9e4ed17d0b7b40ee244a3ee0dd55f`. A phone build signed with a different private key requires that original key; do not uninstall to bypass a signature mismatch.
5. Open the app and confirm your location, timezone, calculation method, Asr preference, Isha boundary, records and files. The first launch rebuilds reminder/widget data from saved state.
6. Previous release artifacts remain intact. No PHP/MySQL or SQLite schema migration is required for this release. Do not import `install.sql` into an existing production database or replace the hosting configuration.

## What changed

- Home shows the next prayer countdown, current prayer's ending time/countdown, today's compact progress and relevant pending routines.
- Prayer opens on Today. Each obligation has start/end, its actual status, live remaining time and explicit completion. Calendar opens the selected date's saved records. Report preserves every required statistic in readable mobile cards/table cells. Pending Qaza, previous Qaza, Friday midday choice and corrections remain available.
- A prayer becoming due, an appearing reminder, snooze, close and expiration cannot create a completion. The due Home action says “Record prayer”; “I Prayed” remains an explicit confirmation action. Qaza completion records the specific prayer exactly once and no longer creates another notification. Qaza does not restore on-time streaks.
- Native notifications and Enforcer use typed actions with account/event validation and durable replay rejection. Snooze replaces only the reminder event; close dismisses without changing worship status. Old notification actions cannot complete an event after it is snoozed. Existing SQLite transactions and sync queues are retained.
- Enforcer uses a rounded emerald/ivory or dark screen, scrollable published scripture/translation with attribution, accessible actions, smooth native slide-up and per-second countdown. System animation settings control motion. Test Enforcer does not offer a worship-completion button.
- Unlocked delivery attempts `TYPE_APPLICATION_OVERLAY`; background Activity launching is not the primary overlay mechanism. Locked delivery uses a dedicated non-exported Activity and permission-gated full-screen notification intent. It never dismisses/bypasses the keyguard. **Wake Screen for Enforcer** defaults off. Notifications are posted first and remain the fallback.
- More groups learning/reflection, everyday tools and app/account resources, with Help/About. Progress provides Overview, Statistics, Personal Journey and Garden access. Existing routine forms, files, private activities and features remain available.
- The Qibla bearing formula and native true-north/display-orientation correction have reference tests; continuous rotation and calibration/missing-sensor guidance are preserved.
- Four real native home-screen widgets: Prayer, Streak, Islamic Garden and Daily Progress. Add through the Android launcher. Resize for medium/large presentation. Tap to open the relevant app screen; tap the Streak title to select Overall/Fajr/Dhuhr/Jummah/Asr/Maghrib/Isha. The Garden uses the existing saved completion-to-plant-stage rule. Explicit Friday Dhuhr choices are respected by native reminders. Widgets render only permitted worship summaries, not private records or credentials. Signed-out account widgets show a sign-in state. Widget refresh uses durable saves, WorkManager, launcher updates and one boundary alarm; no permanent application per-second background service is used.

## Verification results

Final results and the actual lint/signature summary are recorded in `review-v0.3.3/TEST-RESULTS.md`. Unit, browser, native JVM, SQLite, instrumentation and physical-device testing are distinct. Screenshot evidence is in `review-v0.3.3/`; the code/video findings and checklist are in `V0.3.3-AUDIT.md`.

Intermediate checks found a widget clock import issue and a consumed-reminder replay test failure, and a one-millisecond nondeterminism in the native prayer engine. Incidental Java Calendar milliseconds are now normalized to second precision. These were corrected before final packaging; earlier failing runs are not release validation.

## Android and device limitations

- Android/OEM policy can block background foreground-service starts, overlays, full-screen intents and waking the screen. Exact-alarm denial uses the supported inexact fallback. Android 15+ narrows the overlay-permission foreground-service exemption; holding overlay permission alone does not guarantee a service start. The app logs delivery failures and keeps the posted notification available.
- Android 14+ may deny full-screen intent access. Reminder settings show restricted access and link to the system setting where available. DeenPath does not claim a calling role or disguise itself as an alarm-clock app, and does not use Accessibility/device-administrator privileges to bypass restrictions.
- Launcher/notification countdowns use Android chronometers. Boundary refresh is subject to Android delivery restrictions, especially without exact-alarm access; a host may briefly show an expired or negative chronometer until the boundary refresh. It must never turn that expiration into a completion. Ending times remain visible.
- All four widgets were created on XOS; Streak configuration and Daily Progress compact-to-large resizing were verified. Other widget sizes, font scales, themes and launcher implementations still require device QA. Prayer selection is supported for Streak; routine selection is not included.
- Enforcer is intentionally short-lived (three minutes) and dismissible. System navigation stays accessible. Android Force Stop cannot be bypassed; open DeenPath again to resume scheduling.
- Extreme coordinates or invalid calculated boundaries show an unavailable/error state rather than invented end times. Isha follows the existing configured midpoint-of-night/next-Fajr convention, not a universal assumption.
- A physical Infinix X6725B / Android 15 was used for upgrade, data, navigation, reminder and launcher checks. See [the device matrix](review-v0.3.3/DEVICE-QA.md) for observed results and remaining limitations. No Android instrumentation runner was used.
- No production database was changed. Live registration/login, MySQL synchronization, account isolation on a server, cross-device restore, Garden progression over real usage and live Gemini/fallback requests remain **unverified**. Local logic, persistence fixtures and browser flows do not substitute for those checks. Existing user-supplied keys, provider fallback, verified offline learning and conversation storage are preserved. No mandatory paid provider was added.

Check all four widget sizes/empty states and Garden data against the app. Calibrate Qibla away from interference and verify against a physical reference. ## Rebuild and package

Use JDK 21, SDK/build tools 36 and the **existing signing identity**. From the project root: `npm test`, `php tests/backend.php`, `php scripts/lint.php`, `python tests/sqlite_migrations.py`, `npm run android:sync`; then `android/gradlew.bat -p android testDebugUnitTest assembleDebug lintDebug --no-daemon`. Browser tests use the local Vite preview (`DEENPATH_TEST_URL` optionally selects its URL). `node scripts/package.mjs` writes only `deliverables/v0.3.3/`; `node scripts/verify-artifacts.mjs` checks archive exclusions, native classes, exact current web/native assets and checksums. Keep keys/configuration outside source archives.

Platform references: [Android 15 background-service changes](https://developer.android.com/about/versions/15/behavior-changes-15), [Android 14 full-screen intent changes](https://developer.android.com/about/versions/14/behavior-changes-14), [RemoteViews widget chronometer API](https://developer.android.com/reference/android/widget/RemoteViews).
