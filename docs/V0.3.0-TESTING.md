New TypeScript cases exercise independent prayer streaks, historical best preservation, Qaza not restoring on-time streaks, legacy Qaza corrections containing both timestamp fields, unknown versus confirmed-missed entries, period totals, previous-Qaza separation, grouped completion counts, one Friday midday slot, original recorded windows after travel, legitimate corrections and overall five-prayer completion. Habit tests cover independent statistics, ten occurrences counting as one unsuccessful day, unanswered days, per-day/per-occurrence task generation and deterministic deduplication. Freeze restrictions cover Nafl, custom and generated activities. Shared rules test Qibla bearings, civil Hijri dates, end dates/weekdays, quiet hours and clamped date ranges.

Guidance fallback tests inject provider responses: billed API priority, quota/rate-limit fallback, disabled fallback on authentication error, network failure/all unavailable, bounded request counts and offline behavior without calling an invented Rasikh endpoint. These are routing unit tests, **not real Google credential or HTTP response tests**.

PHP tests additionally reject plaintext fields in encrypted records, duplicate historical completion IDs and over-completed Qaza; enforce Freeze restrictions and compare the civil Hijri fixture with TypeScript/Kotlin. They do not establish live MySQL authorization. The SQL migration is additive and reviewable; it has not been applied to the owner's hosting database here.

Native JVM tests include the existing one-alarm stress driver, empty/overdue schedules, merge safety, multipart encoding, prayer calculation parity, sound-channel identity and routine periods, plus weekday/end-date rules, civil Hijri parity, overnight quiet hours, AES-GCM round-trip with fresh IVs, wrong-key rejection and ciphertext tamper rejection. The crypto primitive used by private records is the tested implementation. Android Keystore, PIN/biometric prompts and lifecycle behavior still need device testing.

Browser checks retain the v0.2 counter, persistence, RTL, typing, deletion/toast and dark-theme regressions under consolidated navigation. New flows verify previous Qaza does not inflate prayer totals, private per-day recovery deduplication, no browser plaintext admission persistence, learning progress, full Guidance notice/follow-up draft, calendar navigation and honest no-sensor fallback at 320px. Prayer report and dark Qibla screenshots were visually inspected. The browser uses localStorage/ephemeral private memory, not native SQLite or sensors.

During development, an old fixture expected unknown prayers to be automatically missed; it was updated for the explicit new requirement. A missing lesson follow-up draft was fixed. A calendar assertion incorrectly assumed every Hijri month had thirty days and was corrected to accept twenty-nine or thirty. The final listed suites pass; no unresolved automated failures are intentionally omitted.

No Android device is attached. Unexecuted physical cases: actual ringtone-picker selection and playback, notification permission/delivery, expanded notification content, overlay over Instagram/YouTube, screen lock, reboot/force-stop, biometric enrollment/cancellation, PIN retry delay, screenshot/recent-app protection, encrypted backup across two devices, compass calibration/accuracy and OEM battery rules. No production hosting configuration or personal AI credentials were supplied: live authentication/sync, cross-user SQL/file isolation, email and paid/free Gemini calls remain unverified. A passing debug build is not production-release certification.

Reproduce with `npm test`, `php tests/backend.php`, `npm run check:php`, `python tests/sqlite_migrations.py`, `npm run android:sync`, Gradle `assembleDebug testDebugUnitTest`, and `npm run test:ui` against `npm run preview`. Then run `node scripts/package.mjs` and `node scripts/verify-artifacts.mjs`, and verify the APK using Android SDK `apksigner`. Follow [the install and phone configuration guide](V0.3.0-UPDATE.md).
