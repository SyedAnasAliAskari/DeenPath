# DeenPath 0.3.0 — start here

Install `deliverables/v0.3.0/DeenPath-0.3.0-debug.apk`. The Android ID remains `org.salahguard.app`; the SQLite database remains `salahguard.db`, and the existing `/salahguard/api.php` URL and private hosting directory remain valid. Version code 3 supports updating a remaining SalahGuard installation with the same debug certificate. v0.1 and v0.2 deliverables are retained.

If SalahGuard was already uninstalled, Android normally removed its local database and documents. This build cannot reconstruct unsynced records. Configure the existing API and sign in to retrieve previously synchronized records. Do not import the fresh-install schema over an existing database.

## Configure the phone

1. Confirm city, coordinates, time zone, calculation method and prayer windows in More → Settings. Travel Mode can update location while the app is visible; no background location permission is used.
2. Choose notification sound and English/Urdu reminder meaning, grant notifications/exact alarms as desired, then use the existing Test Notification action. Expand the notification to see the real verse. Quiet hours affect nonessential reminders; prayer controls remain separate.
3. In Prayer, choose the real tracking start date. Unrecorded prayers remain unknown; explicitly correct their status when known. Correcting an on-time entry requires an actual timestamp inside its recorded window. Previous Qaza is entered separately. Friday selection is a record of the user's circumstances, not an automatic legal ruling.
4. In Protection, optionally set a 6–12 digit PIN. Native biometric unlock is available where supported; the app PIN is the fallback. Configure auto-relock and discreet reminders. Generated activities are voluntary personal commitments, never prescribed punishment or mandatory expiation.
5. **Export an encrypted recovery backup from Privacy & recovery backup before uninstalling or moving phones.** Use a unique password of at least 12 characters. Android's document picker writes the backup to your chosen location. It contains encrypted records and a password-wrapped encryption key, not a plaintext PIN or provider key. On a new installation, sign into the same account, restore the backup/key in the private section, then sync. Keep the backup and password safe; there is no server-held recovery key.
6. Guidance supports documented **Gemini REST** connections only: your billed Gemini project/key first, your own Gemini free-tier key second if fallback is enabled. Billing/free-tier eligibility comes from the actual Google project, not the UI label. Obtain your own key from [AI Studio](https://aistudio.google.com/apikey), select an available model and test. Keys are device-local and must be entered again after reinstall. No key is required for offline learning.

Google's [current terms](https://ai.google.dev/gemini-api/terms) impose age, region and developer/professional-use restrictions; this integration is for eligible evaluation, not a claim that general consumer distribution is permitted. Free-tier submitted content and responses may be used to improve Google's products and reviewed by humans. Do not submit sensitive data. Paid requests and connection tests may incur charges. OAuth documentation does not establish a simple Google Sign-In flow that automatically provisions each user's own Gemini project/quota; this build uses explicit personal API keys. Rasikh remains unavailable because its documentation/terms could not be retrieved; no endpoint or entitlement is invented. See [provider and privacy review](V0.3.0-SECURITY.md).

## Existing hosting upgrade

Back up the existing database and private PHP files. Import **only** `backend/sql/migrations/003_deenpath.sql` into the existing database. It adds owner-scoped `qaza_history`, `milestone_events`, `learning_progress`, `private_records` and a schema migration marker using `CREATE TABLE IF NOT EXISTS`; it never drops or resets existing records. Replace private `backend/src/` PHP files while retaining `config/production.php`, upload storage, real paths and credentials. The public `api.php` route and hosting names stay unchanged. Fresh installations may use the current `install.sql`; existing accounts must use the additive migration.

SQLite upgrades from versions 1/2/3 to 4 add a schema metadata table; existing snapshots, records, operations, files and reader positions remain. New entity records use the established transactional snapshot/queue and optimistic conflict handling. Concurrent historical Qaza edits produce an explicit version conflict rather than silently decrementing a shared counter.

## Verification and boundaries

Read [the test report](V0.3.0-TESTING.md) and [limitations](V0.3.0-LIMITATIONS.md). Phone sound, notification delivery, overlay behavior, biometrics, document-picker recovery, compass accuracy, reboot and OEM restrictions still require physical-device tests. No configured hosting or provider credentials were supplied; live login/sync/mail/SQL authorization and actual Gemini responses are not certified by mocked/local tests.

Trademark and DeenPath brand-name availability require verification before public launch. This is an installable **debug** build; production signing remains a private manual process described in BUILD.md. Islamic milestones are motivational indicators, not promises of divine reward. No new Hadith quotations or unsupported religious rulings were fabricated.
