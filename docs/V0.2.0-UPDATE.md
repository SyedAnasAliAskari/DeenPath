# SalahGuard 0.2.0

## Upgrade the installed phone app

Install `deliverables/v0.2.0/SalahGuard-0.2.0-debug.apk` **over the existing installation**. Keep the same package ID (`org.salahguard.app`) and debug signing key; versionCode is now 2. Do not uninstall or clear app data. Existing v0.1.0 deliverables remain in `deliverables/` and a backup is in `deliverables/archive/v0.1.0/`.

SQLiteOpenHelper migrates database versions 1/2 to 3 without dropping user data. The new table holds native reader metadata. Existing snapshot format, profile, records, pending queue, documents and reading positions are preserved. Legacy per-reminder AlarmManager entries are cancelled on first upgraded launch; the app then uses one fixed dispatcher alarm over its SQLite reminder queue.

## Fixed owner-reported issues

1. **500 concurrent alarms:** the old 30-day plan could request 600 prayer alarms before routines. The new queue schedules one OS alarm for the next due item, cancels/replaces it safely and renews the plan with WorkManager. Recurring reminder metadata does not allocate more OS alarms.
2. **Delete dialog remaining open:** a notification-scheduling exception previously interrupted the handler after the local deletion but before closing. Rescheduling is now a separate best-effort operation. A locally successful deletion closes its confirmation; persistence errors still report failure.
3. **Toasts remaining visible:** messages now dismiss automatically after six seconds and remain manually dismissible.
4. **Dark theme:** page background and text now use theme tokens along with the cards, controls and dialogs. Follow System, Light and Dark are available. An existing explicit dark choice is migrated.
5. **Notification sound selection:** a single button opens Android's native notification-ringtone picker. Per-stage sounds are optional under an expandable section. An explicit sound change creates a stable new channel ID because Android channel audio cannot be changed in place. Silent mode, notification volume, DND and manufacturer policy still apply.
6. **Arabic-only reminders / references only:** notifications now include the selected English or Urdu meaning first, then the original Arabic verse, reference and Tanzil attribution. Expand the notification to read the full text; opening the app is optional. The overlay and in-app reminder include the same selected translation. Arabic-only remains an explicit choice.

## Added or completed

- New vector crescent/mosque/arch identity; light/dark SVGs and PNGs, adaptive foreground/background, Android 13 monochrome icon, notification icon and splash branding. Launcher appearance is controlled by the launcher/system; app theme switching does not promise to switch ordinary launcher icons.
- Explicitly enabled native `TYPE_APPLICATION_OVERLAY` reminder, with close, I Prayed/Qaza and snooze. It is short-lived (90 seconds), never locks another app and does not draw on the lock screen. Restricted starts, locked screens and short landscape screens retain notifications.
- Test Notification and Test Enforcer actions schedule about fifteen seconds ahead. The UI reports scheduling/permission state, **not proof of delivery or playback**.
- Network-constrained WorkManager sync, retries/backoff, unique work and a shared sync lock. Three-way snapshot merges preserve new foreground edits while background requests are acknowledged. Tokens rotate with compare-and-set protection against logout races. A different account/server identity stops an old sync job.
- Separate pending-record/file counts and connection status. The last-successful-sync field updates only when the server has confirmed the pending batch.
- Foreground/background data-change signals, routine-reminder suppression after completion, per-stage repeat/snooze controls, image zoom/resume, native PDF navigation/zoom/resume and a completion action for attached routines.
- Email editing requires the current password and revokes other sessions; changed email becomes unverified. No MySQL schema change is required for v0.2.0. Replace private PHP source after backing it up; do not re-import the installation schema over existing tables.
- Fifteen unmodified Tanzil verses with English Pickthall and Urdu Jalandhry translations. All core/new UI dictionary keys have offline Urdu/Arabic values. Unknown diagnostic errors use a localized generic message. Android/vendor sound names are shown as supplied by the system.

## Native reminder test on your phone

1. Open Settings. Confirm city, time zone, method and today's prayer times. Leave silent mode off for the sound test.
2. Tap **Notification sound**, choose an audible system sound in Android's picker, and confirm it. Raise the phone's **notification** volume. DND must allow the notification if you expect a sound.
3. Select **Quran reminder translation → Arabic + English** or **Arabic + Urdu**.
4. Tap **Test notification**, allow notification permission, and put SalahGuard in the background. Wait approximately fifteen seconds; inexact alarms can be delayed. Confirm actual arrival and sound yourself. The notification title is clearly marked as a test; its body carries a verified Quran verse and your selected translation.
5. Expand the test notification and check the Arabic verse, selected translation, reference and source. You can verify this without opening SalahGuard or waiting for an actual prayer. Also verify a real upcoming prayer reminder. Do not fabricate completion timestamps.
6. Enable **Show above other apps** only if wanted; allow the permission in Android's settings. Return to SalahGuard and use **Test Enforcer reminder**. The test does not record a real prayer completion.
7. Repeat the test with **Instagram open**, **YouTube open**, and SalahGuard backgrounded. The overlay may fall back to a notification if Android blocks the foreground-service start or the screen is too short in landscape.
8. Repeat with the **screen locked**: expect notification fallback, not an overlay over the lock screen. Check both collapsed and expanded content. Android may conceal content on the lock screen according to the phone owner's privacy settings.
9. Reboot, unlock once, leave SalahGuard backgrounded and test an actual scheduled reminder. WorkManager restores/renews the native schedule. A force-stopped app must be opened manually before Android resumes its work.
10. Deny notification permission, exact-alarm permission and overlay permission separately; confirm the settings guidance and fallback. Test battery restrictions and different sounds. Record phone model/API level and actual results; these physical-device cases have not been executed here.

## Platform and content boundaries

Overlay services start only for the opted-in, time-sensitive reminder and stop after dismissal/timeout. Android 12+ foreground-start rules and the Android 14+ declared `specialUse` type apply. Distribution through Google Play would require the corresponding policy declarations/review. No Accessibility Service, device lock, continuous app monitor or Usage Access permission is used. UsageStats requires special access and polling to infer newly opened apps; it is not used to maintain an unrelated always-running monitor, and no usage data is uploaded.

Rasikh documentation was checked again and could not be retrieved. Endpoints, authentication, grading, licensing and offline permissions could not be verified, so no Rasikh integration or new Hadith quotation was invented. The bundled religious reminders are verified-source Quran excerpts. Preserve `CONTENT-LICENSE.txt`; translations retain Tanzil's noncommercial distribution terms.

Live hosting authentication, cross-user SQL/file checks, mail delivery and actual phone behavior require the owner's configured service/device. The automated report distinguishes these from local checks. Release signing remains a private manual step; this artifact is a debug build.
