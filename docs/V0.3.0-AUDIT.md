# DeenPath v0.3.0 foundations audit

The existing project is React 19 / TypeScript / Vite inside Capacitor 8, with a Kotlin bridge. SQLite `salahguard.db` version 3 stores a transactional JSON snapshot plus indexed records, queued operations, reminders and reader metadata. PHP uses an explicit entity allowlist and owner-scoped JSON tables, operation UUID deduplication, optimistic versions and incremental changes. Android WorkManager and the foreground share a three-way merge and a native sync lock. The v0.2 dispatcher allocates one AlarmManager alarm; notification channels use native ringtone URIs. Existing offline prayer calculations, routines, counters, freeze replay, garden, readers, authentication, exports and private files are retained.

Already present: five prayer windows, Qaza timestamps, voluntary routines and scheduled Tasbih, daily/weekly/monthly/yearly/interval schedules, travel foreground location updates, three languages/RTL, theme modes, native translated Quran notifications, dismissible overlay and reminder tests. Partially present: prayer history/statistics, recurrence eligibility, private storage, travel settings and verified educational excerpts. Missing: independent prayer reports/streaks, historical Qaza provenance, Friday slot selection, protected habit check-ins/recovery, Nafl type, journal, learning progress, Qibla sensors, Hijri scheduling and Guidance.

Dependency order: (1) shared obligation/status, date-range and recurrence models, additive entity migrations and branding/navigation; (2) prayer reporting/Qaza/Friday and consolidated progress; (3) encrypted private records, privacy authentication and habit/recovery/journal flows; (4) native reminder extensions, Qibla/Hijri/travel; (5) shared verified lessons and secure user-owned provider connections with explicit consent; (6) regression tests, Android assembly, signing and artifact verification. The package ID, SQLite name, API route version and hosting directories remain unchanged. v0.2 deliverables are retained.

No production configuration or connected Android device was found. Live hosting, provider credentials, biometric behavior, compass accuracy and OS delivery require separate verification. Provider integrations must use official documentation; Rasikh must remain unavailable if its capabilities/terms cannot be verified. A new product name requires trademark/brand availability review before public launch.
