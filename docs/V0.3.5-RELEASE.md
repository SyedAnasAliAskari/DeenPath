# DeenPath 0.3.5

Android version code 8. Install the APK over your existing app; keep the SalahGuide folder name and existing app storage.

## Changes

- Personal activities is now Secrets: private habit name, description and a chosen Tasbih or Nafl penalty. Secrets are cards with a daily Yes/No check-in, an avoidance streak and one app point per secret per avoided day. These private points are separate from routine Freeze Points. Retries cannot award twice.
- A Yes answer adds one anonymous Tasbih counter or a Nafl routine. Prayer shows the pending Nafl Rak’ah total and opens the Nafl stack. Secret names and descriptions remain encrypted in the private space. Answer corrections cancel untouched penalties while preserving worship already counted or completed. Earlier private recovery tasks remain accessible.
- The end-of-day Enforcer asks about pending Secrets. Locked private space hides names and requires normal unlocking before answers. Configure its daily time in Secrets; enable overlay access in Enforcer settings. Both prayer and Secrets previews are explicitly non-recording.
- PDF and image readings display within their Dua, Ayat or Tasbih card. Android PDFs have inline page previews and page controls. The standalone routine file-library section is removed. Deleting a routine deletes its owned attachment and queues its cloud deletion; shared legacy documents and profile images are protected.
- Prayer Enforcer previews show I Prayed (or Complete Qaza after the window ends), with an explicit preview-only response. Real prayer actions retain window and duplicate-completion validation. Security Back returns to Secrets.

## Verification

77 TypeScript logic tests, 60 Android unit tests, 33 browser workflow checks, 30 backend checks and three SQLite migration fixtures passed. Android build and lint passed (0 errors, 87 warnings). Production build retains the existing bundle-size warning.

The connected Infinix accepted the upgrade in place. Prayer preview displayed I Prayed; Secrets preview displayed No/Yes, Snooze and Close. Preview taps left records, pending operations and account owner unchanged. Test reminders were cancelled. Private screenshots remain protected; device artifacts are excluded from the source archive. Actual Secrets admissions and worship were not fabricated on the phone. Encryption/biometric settings were not changed.

Real locked-space biometric interaction, all-day alarm delivery/Doze and native PDF visual paging with a user document remain manual acceptance checks. Native PDF rendering compiled and is covered by browser attachment workflow checks, but those checks do not substitute for a physical-document test. Hosted database, mail, cloud deletion HTTP integration and production credentials were not exercised.

No database migration is needed from 0.3.4. For older backend installations, deploy the bundled private backend before syncing After Namaz routines (introduced in 0.3.4); preserve production configuration and never import install.sql over an existing database. App ID and signing certificate are unchanged.
