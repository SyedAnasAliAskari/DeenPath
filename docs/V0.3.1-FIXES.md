# DeenPath 0.3.1 — layout and reminder fixes

Install `deliverables/v0.3.1/DeenPath-0.3.1-debug.apk` **over the current app**. Do not uninstall or clear data. The package remains `org.salahguard.app`, versionCode is 4, and the existing debug signing key is retained. v0.3.0 artifacts remain in their own folder. No SQLite or MySQL schema migration is introduced by this patch; an older backend still needs the v0.3.0 additive migration before syncing its new entities.

## Fresh-install error

The first Android save called private-storage account scoping before a snapshot existed. `JSONObject("")` threw “End of input at character 0,” preventing the first snapshot from being saved. Later edits repeatedly reached the same path. `SnapshotDocument` now recognizes blank/new-install storage as an empty document with local scope. Existing account IDs are retained; corrupt nonempty JSON still fails rather than being silently overwritten. The same safe scope reader is used by private storage, provider storage and chat storage.

## Test reminders

The reminder dispatcher previously rejected a test if there was no saved app snapshot. This could happen after the first-save error, making a successful test scheduling response produce no notification. Test delivery now works independently of worship records. A short process timer also triggers the same single dispatcher after about fifteen seconds while the process is alive; the existing OS alarm remains the fallback and consumed queue entries prevent duplicate dispatch. Exact-alarm denial can still delay the background fallback, and the UI now says so.

Test Enforcer is a one-off overlay test and no longer depends on permanently enabling prayer overlays. If Display over other apps permission is missing, the button opens Android settings and explicitly asks the user to return and tap the test again. Android background-start restrictions, lock screen and short landscape layouts still use notification fallback. No Accessibility Service or continuous background monitor was introduced.

To check on the phone: open More → Settings → Prayer reminders, select an audible native sound, grant notification permission and run Test notification. Wait about fifteen seconds, then expand the notification. For Test Enforcer, grant the overlay permission when asked, return and run the test again. Test once with DeenPath visible and once after opening another app. Inspect actual sound/arrival yourself; successful scheduling is not a delivery receipt.

## Simpler screens

1. **Home:** retains the next prayer, today's prayer rows and routines; removes the duplicate daily ring and decorative garden card. The prayer list uses flexible name/time/status/action cells instead of fixed narrow columns.
2. **Settings:** opens as a five-row category menu. Only the selected category is visible. Test buttons are easy to reach; stages, quiet hours and other advanced controls are expandable.
3. **Prayer and Progress:** tracking/filter controls, history, trends, routine statistics and personal records are available on demand. Selecting a prayer report row opens its detail view rather than stacking it below the full report.
4. **Forms and private activities:** routine fields follow the chosen kind/frequency. Daily Quran forms no longer expose weekday/month-day/interval/Tasbih fields. Private check-ins show one selected habit, occurrence counts only for a slip, and optional reflections behind an expandable row. Saving a counter/check-in no longer hides and rebuilds the entire private page.
5. **Close controls and collisions:** dialogs and toasts keep a 44px close target on the physical right, including RTL. Native overlay heading direction is handled separately so its close control also stays right. Buttons wrap safely; title/status cells can shrink without overlapping actions.
